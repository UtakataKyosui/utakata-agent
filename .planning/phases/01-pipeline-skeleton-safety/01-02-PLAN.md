<feature>
  <name>validate_pre_pr gate function</name>
  <files>issue_resolver/validation.py, tests/test_validation.py</files>
  <behavior>
    - validate_pre_pr(ctx) with clean state raises nothing
    - validate_pre_pr(ctx) when git diff shows a file NOT in ctx.affected_files raises ValidationError matching "Out-of-scope"
    - validate_pre_pr(ctx) when changed file matches test_*.py pattern raises ValidationError
    - validate_pre_pr(ctx) when changed file matches *_test.py pattern raises ValidationError
    - validate_pre_pr(ctx) when os.path.exists("pyproject.toml") is True and bandit returns non-zero raises ValidationError matching "andit" (bandit/Bandit)
    - validate_pre_pr(ctx) when os.path.exists returns False skips bandit entirely
    - validate_pre_pr(ctx, token_count=150_001) raises ValidationError matching "oken"
    - validate_pre_pr(ctx, token_count=150_000) raises nothing (at exactly 150k is OK)
  </behavior>
  <implementation>
Define `class ValidationError(Exception)` with docstring "Pre-PR validation failure. Message is posted as Issue comment." Implement `validate_pre_pr(ctx: IssueContext, token_count: int = 0) -> None` checking 4 conditions in order as specified in CONTEXT.md. Use `subprocess.run` with `shell=False`, list args. Test patterns: `r"^test_.*\.py$"`, `r".*_test\.py$"`, `r".*\.test\..*$"`, `r"^tests/"`. Use `import os; os.path.exists(...)` for Python detection. Keep the function pure and deterministic given its subprocess mock points.
  </implementation>
</feature>
